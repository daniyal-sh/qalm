2 · Live AI loop: the agent can run on any machine

The device syncs CRDT ops to a relay. A server-side indexer keeps an AI-ready view of the notebook, and an MCP server exposes that view to agents.

DeviceWrites strokes locally and works offline. Pushes ops when the writer pauses
→
Sync relayWebSocket. CRDT ops, revision cursors and presence
→
IndexerClusters ops into blocks, recognizes handwriting and math, and renders crops on demand
→
MCP serverRemote over Streamable HTTP. OAuth, plus a share token for each session
→
Any agentClaude, a tutor service, or the student's own assistant
↩ The agent writes back with annotate(). Its marks land on a separate AI layer that the student can show, hide, accept or clear.

3 · Four ways to make handwriting AI-readable

Each option trades cost against how much the model can actually understand. qalm should support all four and send the cheapest one that is good enough.

AScreenshots

Send a rendered image of the page.

  • The model reads it well, and it's easy to build
  • About 2.3k tokens every time it looks, even if only a comma changed

BStroke vectors (Q-ink)

Simplify, quantize and delta-encode the strokes.

  • Very cheap for small changes, graphs, arrows and diagrams
  • Models read handwriting poorly from coordinates. A full page costs more than a screenshot

CRecognize, then send text

Run handwriting and math recognition, then send text, LaTeX and shapes with confidence scores.

  • The cheapest option and the easiest for the model to reason over
  • Recognition can be wrong. Diagrams don't survive it

DLayered and diff-based recommended

Send C by default, fall back to B and A for each block, and send only what changed.

  • The agent receives diffs once the student pauses, with a confidence score for each block
  • When confidence is low, it can ask for a crop of that block

4 · One look at a full page of math work

Approximate tokens for one look at about 12 handwritten lines. Images are estimated as width × height ÷ 750.

Raw input samples (x, y, pressure, tilt and time for every point) would be roughly 140k tokens, so they're left off the chart. Per change rather than per page, the gap grows: a single new line costs about 15–40 tokens as text, against about 2.3k for a fresh screenshot.
