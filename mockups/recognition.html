1 · Short answers

Is ML Kit Digital Ink heavy?

No. Each language is a model of about 20 MB, downloaded when needed. It runs offline on Android and iOS and supports more than 300 languages. It reads strokes in the order they were written, which helps with cursive. Its gaps: no math, and no Windows or macOS version.

Are vision models accurate?

Good, not perfect. Handwriting is still the hardest kind of OCR for them. They also have a known flaw: they "fix" mistakes, silently changing a wrong exponent into the right one. Our input is clean, digitally rendered ink rather than photos, which helps a lot. So use them as one reader among several, never as the only one.

3 · The pipeline: free first, paid only when it matters

Most ink never leaves tier 1. Tiers 2 and 3 run only on notebooks with AI access turned on.

1
On the device, while you write

The device's stroke recognizer reads each block within milliseconds. That powers handwriting search, lasso-to-text and the Q-ink text. Only text and confidence scores are synced, a few bytes per block.

freeofflineevery notebook
2
On the server, only where needed

The server renders a clean crop of the block from its strokes, with no paper lines, and runs a vision model on it. That happens only when the block looks like math, the confidence is low, or it's a diagram. The result is cached by content hash, so a block is recognized once, however many times agents read it.

AI-enabled notebooks onlybatchedcached forever
3
The agent looks for itself

If the two readers still disagree, Q-ink sends both readings marked as low confidence. The agent can then call render_region and read the crop with its own vision model, on the agent owner's bill.

4 · How we get high accuracy

  1. Two independent readers. Stroke order from tier 1 and pixels from tier 2. If they agree, confidence is high. If they disagree, both readings go into Q-ink and the block is flagged.
  2. Perfect input images. Crops are rendered from vectors: black ink on white, the right size, with no skew, shadows or ruled lines. That's easier than any photo benchmark.
  3. Literal-transcription guard. Prompt the model for a verbatim transcription, then diff the result against the stroke reader character by character. Any "correction" either reader didn't see is rejected, so the model can't fix your mistakes.
  4. Context. Pass the previous two lines and the notebook's vocabulary (names, terms you've written before) as hints.
  5. Corrections you make. Tap a word to fix it. Each fix becomes a dictionary entry for you and, if you opt in, a test case.
  6. Measure before choosing. An eval set of real qalm ink, scored by character error rate for text and exact-match plus character error rate for LaTeX. Every candidate model is benchmarked on it, and the winner is the best accuracy per dollar.

5 · Server cost per 1,000 handwritten lines

Estimates for tier 2 only, assuming a 600×80 crop of about 64 image tokens, about 200 input tokens per line in total, and 25 output tokens.

A heavy user writes perhaps 3,000 lines a month. Maybe a third of those are in AI-enabled notebooks and need tier 2, which comes to about 3 cents per heavy user per month on the cheapest options. GPU figures assume an L4-class GPU at about $0.70 an hour reading about 10 lines a second. That still needs measuring.
